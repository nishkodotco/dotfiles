# VS Code keyboard shortcuts

| File | For |
|---|---|
| `keybindings.mac.json` | macOS |
| `keybindings.windows.json` | Windows and Linux (Cmd becomes Ctrl) |
| `apply-keybindings.sh` | copies the right file into VS Code on macOS and Linux |
| `apply-keybindings.ps1` | copies it into VS Code on Windows |

`keybindings.json` in this folder is the older file that `./install.sh` links on macOS.
It is not changed here.

## Apply on a machine

macOS or Linux:

```bash
editors/Code/apply-keybindings.sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -File editors\Code\apply-keybindings.ps1
```

The scripts copy into VS Code's user folder and into every profile that has its own
`keybindings.json`. They skip files that are already identical, keep a one-time
`keybindings.backup.json`, and never touch a `keybindings.json` that is a symlink.

## Mac to Windows/Linux keys

Mac Cmd becomes Ctrl, Mac Ctrl becomes Alt, Mac Cmd+Ctrl becomes Ctrl+Alt, and Alt stays Alt.
These got their own Windows key to avoid a clash: Run task (Ctrl+Shift+Alt+T),
Start debugging (F5), Reveal file in Explorer (Ctrl+Shift+Alt+R),
Collapse Explorer folders (Ctrl+Shift+Alt+X), Git open changes (Ctrl+Shift+Alt+V)
and Git push (Ctrl+Shift+Alt+Y).

The Windows file is generated by `scripts/make-windows-keybindings.py` in
`nishkodotco/app.xponent.automation`. Copies also live in `mlverse/.vscode/`.
